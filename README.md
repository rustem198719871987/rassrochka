# Рассрочка.Топ

Веб-сервис для оформления рассрочки (не кредита) продавцами от имени ИП.
Node.js + Express + SQLite, страницы рендерятся на сервере (EJS). Отдельная база данных или сборка фронтенда не нужны.

## Быстрый старт

```bash
npm install
cp .env.example .env        # заполните ADMIN_PASSWORD
node --env-file=.env server.js
```

Откройте http://localhost:3000 и войдите как администратор (телефон из `ADMIN_PHONE`, пароль из `ADMIN_PASSWORD`).
Если `ADMIN_PASSWORD` не задан, пароль сгенерируется и выведется в консоль при первом запуске.

## Роли и сценарий

**Администратор** (`/admin`)
- Добавляет ИП с реквизитами (ИНН, ОГРНИП, банк, БИК, р/с, к/с). Эти реквизиты попадают в договор и в QR-код для оплаты.
- Видит заявки продавцов на регистрацию: «Одобрить», «Отклонить» или «На корректировку» с комментарием.
- Добавляет продавцов вручную, прикрепляет к продавцу несколько ИП, блокирует и сбрасывает пароль.
- Видит все рассрочки, отмечает поступившие платежи, видит просрочки.
- Ведёт стоп-лист клиентов. Вручную одобряет заявки с отказом, если есть основание.
- Меняет наценку (по умолчанию 3 % в месяц) и сроки (по умолчанию 1–6 мес).

**Продавец** (`/register` → проверка администратором → `/app`)
- Регистрируется сам: ФИО, дата рождения, паспорт, прописка, телефон, выбор одного или нескольких ИП.
- Меню: «Создать заявку», «Калькулятор», «Поиск» (по ФИО, номеру договора, телефону, паспорту).
- Оформление в 5 шагов:
  1. Товар, цена, срок, ИП.
  2. Анкета клиента: ФИО, паспорт, прописка и адрес проживания, работа, доход, семья, контактное лицо.
     Паспорт можно не вводить руками: кнопка «Показать QR-код» → продавец сканирует код телефоном,
     фотографирует разворот паспорта, прописку и клиента → «Отправить». Поля заполнятся сами.
  3. SMS-код на телефон клиента. Код подтверждает номер и подписывает согласие на обработку ПД.
  4. Проверка по базам. Найдено совпадение — отказ.
  5. Договор с графиком платежей и реквизитами, подписание кодом из SMS.
- После подписания: документы для печати, QR-код для оплаты и SMS клиенту со ссылкой на страницу оплаты.
- Скан подписанного договора: «Загрузить по QR-коду» → телефон фотографирует страницы по очереди → «Отправить».
  Можно загрузить и с компьютера (JPEG, PNG, PDF). Скан всегда доступен в карточке рассрочки.
- «Платежи»: сколько дней осталось до платежа у каждого клиента и у кого просрочка.
  Оплату наличными в магазине продавец вносит сам, но в график она попадает только после подтверждения администратором.
- «Претензии»: формируются автоматически при просрочке. Продавец печатает претензию и передаёт руководителю магазина.

## Платежи, напоминания и претензии

- **Журнал оплат.** Каждое поступление — отдельная запись: банковский перевод из выписки, наличные или карта в магазине.
  График закрывается только подтверждёнными записями, по порядку платежей. Частичная оплата тоже учитывается.
  Администратор может аннулировать ошибочную оплату, график пересчитается.
- **Выписка банка** (Администратор → «Выписки банка»): файл в формате 1С (`1CClientBankExchange`, «Экспорт в 1С»).
  Поступление с номером договора в назначении зачитывается сразу. Поступление, где совпадает только ФИО плательщика, ждёт подтверждения.
  Остальные можно зачесть вручную по номеру договора. Повторная загрузка той же выписки ничего не задваивает.
- **SMS-напоминание** уходит клиенту за 5 дней до платежа со ссылкой на страницу оплаты `/pay/<токен>`:
  там график, сколько дней осталось и QR-код. Отправка — с 9:00 до 21:00 по Москве. Журнал SMS виден в карточке рассрочки.
- **Претензия** формируется, когда платёж просрочен на 5 дней. В ней таблица долга,
  требование оплатить за 10 дней, реквизиты и QR-код на сумму долга. Статусы: сформирована → передана руководителю →
  вручена клиенту → закрыта (автоматически после погашения долга).
- Сроки (5 дней) и адрес сайта для ссылок меняются в «Настройках».
  Там же кнопка «Запустить проверку сейчас». Автоматическая проверка идёт каждые 30 минут.

## Аннулирование рассрочки

Если клиент отказался или вернул товар, продавец нажимает в карточке рассрочки «Аннулировать рассрочку» и пишет причину.
Запрос попадает администратору (раздел «Аннулирование»): он одобряет или отказывает с комментарием.
Аннулированная рассрочка выделяется светло-красным во всех списках, напоминания и претензии по ней прекращаются,
вознаграждение продавца сторнируется, в аналитике она не учитывается. Если аннулирует администратор — сразу, без запроса.

## Вознаграждение продавца

- Ставки по умолчанию: 1 мес — 0%, 2 мес — 1%, от 3 мес — 2,5% от суммы договора (меняются в «Настройках»;
  там же можно считать процент от стоимости товара). Ставка фиксируется в договоре на момент подписания.
- Продавец видит вознаграждение сразу — в калькуляторе и при оформлении заявки, а после подписания оно начисляется
  на баланс (раздел «Вознаграждение»).
- Продавец отправляет заявку на вывод с номером карты или телефоном для СБП. Администратор переводит деньги
  и нажимает «Выплачено» (раздел «Выплаты продавцам»). Если рассрочку аннулируют после выплаты, баланс уходит в минус
  и удерживается из следующих начислений.

## Аналитика

Администратор → «Аналитика»: прибыль, количество и сумма оформленных рассрочек, поступившие оплаты — за этот месяц,
прошлый месяц, квартал, год, всё время или свой период, со сравнением с тем же отрезком прошлого периода.
Графики прибыли и количества рассрочек по дням или месяцам, разбивка по продавцам, ИП и срокам.
Прибыль = наценка за рассрочку − вознаграждение продавцов. Аннулированные рассрочки не учитываются.

## Хранение файлов

Фото паспортов, клиентов и сканы договоров лежат в `data/uploads/` и **шифруются AES-256-GCM**.
Отдаются они только продавцу этой заявки и администратору. Ключ берётся из `FILES_KEY` в `.env` (64 hex-символа)
или из `data/files.key`, который создаётся при первом запуске.
**Ключ храните в резервной копии отдельно от файлов: без него сканы не восстановить.**
Создать ключ: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.

## Закрыто от поисковиков

Сайт не индексируется: `/robots.txt` запрещает обход, каждый ответ (страницы, файлы, страница оплаты)
несёт заголовок `X-Robots-Tag: noindex, nofollow`, в страницах — `<meta name="robots" content="noindex">`.

## Обновление базы

Структура базы обновляется автоматически при запуске (миграции, `PRAGMA user_version`). Старые данные сохраняются.

## Расчёт

Наценка = стоимость товара × 3 % × число месяцев. Пример: 45 000 ₽ на 3 мес → наценка 9 % = 4 050 ₽,
итого 49 050 ₽, платёж 16 350 ₽ в месяц. Формула в `public/js/calc.js` — одна и та же для сервера и браузера.

## Фото паспорта с телефона

1. В анкете продавец нажимает «Показать QR-код». Код содержит одноразовую ссылку `/m/<токен>`: она действует 30 минут, вход в кабинет для неё не нужен.
2. Телефон открывает страницу загрузки с тремя фото: разворот с фото (обязательно), прописка, клиент. Фото сжимаются на телефоне до ~2000 px. Перед отправкой их можно повернуть.
3. Сервер сохраняет фото в `data/uploads/` (доступны только продавцу заявки и админу) и распознаёт паспорт:
   - **встроенное распознавание, бесплатно и без интернета** (Tesseract, языки eng и rus):
     - машиночитаемая зона внизу страницы с фото (строки `<<<`): ФИО, пол, дата рождения, серия, номер, дата выдачи,
       код подразделения — со сверкой по контрольным цифрам; если прочиталась только вторая строка, берётся она;
     - русский текст разворота (`lib/passport-text.js`): место рождения, «кем выдан», а также ФИО и даты, если МЧЗ не прочиталась;
     - серия и номер красными цифрами у края страницы — если в МЧЗ они не прочитались;
     - «кем выдан» сверяется со справочником кодов подразделений (`lib/fms.js`, данные DaData, CC BY-SA 4.0,
       см. `lib/data/README.md`): совпало — берётся точное название из справочника, иначе текст с фото;
     - адрес со штампа «Зарегистрирован» на странице с пропиской;
   - **Yandex Vision** — необязательно, платно: если в настройках указан ключ, используется вместо встроенного.
4. Анкета на компьютере заполняется сама. Распознанные поля подсвечиваются жёлтым, сомнительные — оранжевым.
   Под полем «Кем выдан» показываются все названия подразделения по коду — продавец выбирает как в паспорте.
   То же работает при ручном вводе: после ввода кода подразделения «кем выдан» подставляется сам (`/api/fms`).

Чтобы телефон открыл ссылку, сайт должен быть доступен из интернета. Если сайт стоит за прокси, задайте `PUBLIC_URL`.

## Подключение внешних сервисов

Ключи SMS.ru и Yandex Vision администратор вводит прямо на сайте: **Настройки → SMS.ru / Yandex Vision OCR**.
Там же кнопка «Проверить» показывает баланс SMS.ru и отправляет тестовое SMS. Значения из `.env` имеют приоритет.

| Что | Как подключить | Без подключения |
|---|---|---|
| SMS | Ключ api_id из личного кабинета sms.ru | Тестовый режим: код пишется в консоль и показывается продавцу |
| Распознавание паспорта (необязательно) | Yandex Cloud: сервисный аккаунт с ролью `ai.vision.user`, API-ключ и ID каталога | Встроенное бесплатное распознавание всех полей и прописки |
| ФССП | Настройки → «Проверка ФССП»: поставщик api-cloud.ru и ключ (или свой `FSSP_API_URL`) | Каждую заявку проверяет администратор (очередь «Проверка ФССП») |
| БКИ / банковские стоп-листы | `BKI_API_URL`/`BKI_API_TOKEN` | Проверка помечается «не подключена» |

### Проверка ФССП (`lib/fssp.js`)

Официальный API ФССП отключён с 2022 года, сайт fssp.gov.ru закрыт капчей от программ; обходить её мы не стали.
Автоматическая проверка идёт через поставщика данных (api-cloud.ru, оплата за запрос): продавец нажимает
«Проверить клиента» — и через несколько секунд заявка одобрена или отклонена, без участия людей.

- Найдены действующие исполнительные производства — автоматический отказ (администратор может одобрить вручную).
- Поставщик не ответил, вернул ошибку или непонятный ответ — это не считается «долгов нет»: заявка уходит
  администратору в очередь **«Проверка ФССП»** (значок в меню + SMS администратору). Продавец видит «Ожидаем решение»
  с таймером на 5 минут; страница обновится сама, когда администратор нажмёт «Долгов нет» или «Есть долги».
- Пока поставщик не подключён, в очередь попадают все заявки.
- Повторная проверка того же человека в течение 6 часов берётся из памяти (не тратит деньги).
- Настройки → «Проверить ФССП» — пробный запрос с показом ответа поставщика.

Свой поставщик: `FSSP_API_URL`/`FSSP_API_TOKEN` в `/etc/rassrochka.env` — POST JSON с ФИО, датой рождения и паспортом,
ответ `{ "found": true|false, "details": "..." }`. БКИ — так же через `BKI_API_URL`/`BKI_API_TOKEN` (`lib/checks.js`).

## Личный кабинет клиента (`/client`, `routes/client.js`)

Клиент входит по **номеру договора и телефону** — на телефон приходит код в SMS (5 отправок в час на номер, 10 с адреса,
60 секунд между SMS, 5 попыток ввода кода). В кабинете: все его договоры на этот телефон, сумма оформления, стоимость,
первый взнос, срок, оплачено и остаток, график со сроками и просрочкой, договор для просмотра и печати.

Оплата из кабинета:
- **СБП** — кнопка и QR-код по ссылке банка, указанной у ИП (ИП и реквизиты → «Ссылка СБП из банка»). Такие оплаты
  приходят в выписке без номера договора: сайт находит клиента по ФИО и предлагает зачесть;
- **QR-код с реквизитами** — сумма и номер договора заполняются сами, оплата зачитывается из выписки автоматически.

Сессия клиента закрывается после 30 минут бездействия; кабинет продавца клиенту недоступен. Без ключа SMS.ru в рабочем
режиме вход закрыт (иначе код показывался бы на экране). Ссылка на кабинет есть на странице оплаты из SMS.

## Выписки банка по почте (`lib/mailbox.js`, `deploy/mail.sh`)

На сервере работает приём почты (Postfix) только для одного адреса — **rustem@ваш-домен** (другой: `MAIL_USER=имя`
при запуске `deploy/mail.sh`). Банк каждый день присылает туда выписку, сайт каждые 2 минуты забирает письма и сверяет
платежи так же, как при ручной загрузке (Выписки банка). Письма после разбора удаляются, итог — в журнале
(Настройки → Почта для выписок).

1. **DNS домена** (панель Timeweb → Домены → DNS): удалите прежние MX-записи и добавьте
   `MX  @  rassrochka.top  приоритет 10` (A-запись `rassrochka.top` уже указывает на сервер). Входящий порт 25 должен быть открыт.
2. `rassrochka-update` — установит Postfix, откроет порт 25 и покажет адрес в Настройках.
3. В интернет-банке включите ежедневную отправку выписки на этот адрес **в формате 1С** (.txt, «1CClientBankExchange»).
4. Когда придёт первое письмо, в Настройках в списке «Последние посторонние отправители» нажмите «разрешить» у адреса банка
   (или впишите его заранее в «Разрешённые отправители»).

Защита:
- принимается только адрес rustem@домен; пересылка наружу запрещена (не «открытый релей»);
- на входе: проверка HELO и домена отправителя, чёрные списки Spamhaus и SpamCop, лимиты частоты, fail2ban;
- сайт берёт письмо, только если отправитель в списке разрешённых **и** подпись банка подтверждена (DMARC, либо
  DKIM/SPF домена отправителя) — поддельная «выписка» с чужого адреса отклоняется; письма посторонних удаляются
  без записи в журнал (только счётчик и 5 последних адресов);
- повторно присланные платежи не задваиваются (проверка по реквизитам документа).

## Безопасность

- Пароли — bcrypt; вход: 10 попыток за 10 минут с адреса и 20 в час на номер; время ответа не выдаёт, есть ли номер.
- CSRF-токен на всех формах; сессия меняется при входе; при смене пароля/телефона и блокировке другие входы завершаются.
- Content-Security-Policy без встроенных скриптов (только файлы сайта), HSTS, запрет фреймов, `nosniff`,
  Permissions-Policy; шрифты и всё остальное — с этого сервера, без сторонних CDN.
- Страницы кабинета не кэшируются браузером (`no-store`) — важно для общего компьютера в магазине.
- Фото и сканы зашифрованы AES-256-GCM, отдаются только продавцу заявки и администратору; тип файла — по содержимому.
- Ссылка с телефона проверяется до приёма файлов; лимиты на SMS (на заявку, продавца и сутки), проверки, API.
- Ошибки в async-обработчиках не роняют сайт (`lib/express-async.js`); сайт слушает только 127.0.0.1.
- **DDoS и перебор** (`deploy/harden.sh`, применяется установщиком и `rassrochka-update`): nginx — 15 запросов/с и
  50 соединений с адреса, вход/регистрация — 10 в минуту, загрузка фото — 20 в минуту, таймауты против Slowloris,
  версия nginx скрыта; fail2ban блокирует нарушителей лимитов (15 мин) и перебор SSH (1 ч); `ufw limit` для SSH;
  SYN cookies. Если настройка nginx не проходит проверку — возвращается прежняя.
- От атак, забивающих сам канал сервера (сотни Мбит/с), защищает только провайдер: подключите защиту от DDoS
  в панели хостинга или проксирование через DDoS-Guard.

## Платёжный QR

Строка по ГОСТ Р 56042-2014 (`ST00012|Name=…|PersonalAcc=…|BIC=…|Sum=…`). Её распознают приложения российских банков
(«Оплата по QR»). Код формируется в `lib/qr.js`.

## Установка на сервер (Ubuntu 22.04 / 24.04)

На чистом сервере под root одной командой (репозиторий открытый):

```bash
curl -fsSL https://raw.githubusercontent.com/rustem198719871987/rassrochka/main/deploy/install.sh | bash
```

Если репозиторий приватный — с токеном GitHub (только чтение содержимого этого репозитория):

```bash
curl -fsSL -H "Authorization: token ТОКЕН" https://raw.githubusercontent.com/rustem198719871987/rassrochka/main/deploy/install.sh | GITHUB_TOKEN=ТОКЕН bash
```

С доменом и HTTPS (A-запись домена должна указывать на сервер): добавьте перед `bash` переменные
`DOMAIN=rassrochka.top EMAIL=почта@mail.ru`. Повторный запуск безопасен — так же подключается домен позже.
Если GitHub с сервера не отвечает, добавьте `SKIP_CODE=1` — домен подключится без скачивания кода.

Скрипт ставит Node.js 22, nginx, службу systemd с автоперезапуском, файрвол (SSH, HTTP, HTTPS),
сертификат Let's Encrypt, ежедневные резервные копии в `/var/backups/rassrochka` (03:30, 14 дней).
Ключи генерируются на сервере в `/etc/rassrochka.env`; пароль администратора показывается в конце установки.

- Обновить до последней версии: `rassrochka-update` (приватный репозиторий: `GITHUB_TOKEN=... rassrochka-update`)
  Код качается по одному файлу и только изменённые файлы (`deploy/fetch-code.sh`): с raw.githubusercontent.com,
  при сбое — с зеркала cdn.jsdelivr.net, каждый файл сверяется с контрольной суммой из GitHub. Так обновление
  проходит и тогда, когда GitHub с российского сервера обрывает `git clone`. Библиотеки (`npm ci`) переустанавливаются,
  только если изменился `package-lock.json`. Повторный запуск установщика без `DOMAIN` сохраняет подключённый домен.
- Журнал: `journalctl -u rassrochka -f`
- Данные: `/var/lib/rassrochka`, код: `/opt/rassrochka`

## Перед запуском в работу

- Разместите сервер в РФ: этого требует 152-ФЗ о локализации персональных данных. Уведомите Роскомнадзор об обработке ПД.
- Включите HTTPS (nginx + Let's Encrypt) и `COOKIE_SECURE=1`.
- Тексты договора и согласия — шаблоны. Их должен проверить юрист.
- Делайте резервные копии папки `data/`: там база и фото паспортов. Ограничьте доступ к ней на сервере.
